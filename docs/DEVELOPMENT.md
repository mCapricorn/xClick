# 开发与验证

## 本地开发

xClick 直接从源码目录加载。在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，打开含 `manifest.json` 的仓库根目录。修改页面特效时编辑 `content.js`，修改设置面板时编辑 `popup.html` 和 `popup.js`。改动后在扩展管理页重新加载 xClick，并刷新已打开的 X 页面。

## 提交前检查

在仓库根目录使用 Git、Python 3.9+ 和 Node.js 20+ 执行以下命令。第一项检查 Git 索引中的文件名和内容，先暂存要检查的改动。随后检查清单与脚本语法，并使用模拟响应验证模型适配。每条命令都应以状态码 0 退出。

```sh
python tooling/check_repo.py
python -m json.tool manifest.json
node --check content.js
node --check popup.js
node --test tooling/ai-replies.test.mjs
```

## 浏览器验收

- AI 回复功能位于 `ai/`，打包时须包含整个目录。分别打开简体中文、繁体中文和英文测试帖的回复窗口，直接点击“AI 生成”，核对所有候选与原帖的语言和字形一致。中英混写时核对是否跟随正文主要语言。再验证候选顺序、追加已有草稿和手动发送流程。真实厂商联调需要相应账号、模型权限和可用额度。

- 打开扩展面板，分别预览点赞、关注、回复和发送效果。更换主题并重新打开面板，核对设置是否保留。
- 关闭声音，核对预览静音；再启用声音并调整音量，核对反馈是否随之变化。
- 页面交互有改动时，使用测试账号在 X 页面验证受影响的鼠标或键盘操作。关闭总开关后确认页面操作仍可用，且不再触发扩展反馈。在 PR 中记录浏览器版本和实测结果。

## 交付与回退

以 `manifest.json` 中的版本号标识交付物。ZIP 根目录应包含清单、页面脚本、面板文件和引用的图标。打包后解压并从该目录执行浏览器验收。商店资料见[提交草稿](../CHROME_WEB_STORE.md)，提交前核对其中的版本和文件名。本地回退时从已验证的旧版本目录重新加载扩展。
