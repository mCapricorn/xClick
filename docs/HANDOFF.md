# 交接与恢复

中途移交任务时，在关联 Issue 或 PR 记录以下内容。

- 目标与尚未满足的验收条件
- 分支、最近提交和未提交修改的位置
- 已执行检查、环境、真实结果和证据位置
- 当前阻塞、下一步操作和负责人

接手者先核对远端分支和提交，再按 DEVELOPMENT 准备环境、复跑相关检查。需要长期保留的决定写入 ADR。

## 排障交接（按需）

在当前 Issue 或 PR 中留下一个接手者能继续执行的实验。

| 内容 | 交接时填写 |
| --- | --- |
| 已证实的事实 | 实际运行的版本或提交、环境、复现步骤、观察结果和证据位置。记录影响结果的人工操作。 |
| 待验证的假设 | 可能的原因，以及现有证据还解释不了的现象。 |
| 下一步与判定标准 | 谁在什么条件下执行哪个操作。预期观察到什么，什么结果会否定该假设。 |

## 备份

项目初始化时指定备份范围、保存位置、访问权限、责任人及恢复验证方法。Git 远端保存已推送的版本记录。未提交工作、Issue、PR、配置及交付产物是否需要独立备份，由项目逐项登记。记录备份时间和实际恢复验证结果。启用外部备份工具时，通过项目配置提供位置和命令。
